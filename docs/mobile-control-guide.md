# 手机控制详细使用指南

本文档说明如何在 IGoLibrary-Ex 中使用手机控制，包括首次配置、启动与访问、局域网和 Cloudflare Tunnel 两种网络方式、Cookie 刷新、任务与预约管理、自动开启、安全注意事项以及常见问题处理

> [!IMPORTANT]
> 手机控制页面拥有启动抢座、全域捡漏和占座、刷新 Cookie、取消任务和取消当前预约等操作权限。访问地址中的 `token` 就是访问凭证，请勿截图公开、转发给无关人员或粘贴到不可信网站
>
> 手机控制依赖电脑端 IGoLibrary-Ex 持续运行。电脑休眠、关机、退出软件或停止手机控制后，手机页面都将无法继续使用

## 📌 功能流程概览

完整流程如下：

```text
完成普通登录
    ↓
在“系统设置 → 网络与接口”选择网络方式
    ↓
局域网：手机与电脑连接同一局域网
Cloudflare Tunnel：确认电脑可以访问 Cloudflare
    ↓
进入“手机控制”页面
    ↓
点击“启用手机控制”
    ↓
用手机扫描二维码
    ↓
查看状态、启动或取消任务、刷新 Cookie、取消预约
```

第一次使用时，软件会自动生成一个随机端口和访问令牌并保存。以后通常只需要启动手机控制并扫描页面二维码

## ✅ 使用前准备

开始前请确认：

1. 已在 IGoLibrary-Ex 中完成普通登录
2. 电脑端软件保持运行
3. 已根据使用场景选择 `本机局域网` 或 `Cloudflare Tunnel`
4. 如果使用局域网模式，手机与电脑能够互相访问
5. 如果使用 Cloudflare Tunnel，电脑能够连接 Cloudflare，必要时已经配置代理或 Clash/Mihomo 兼容模式

## 🧭 两种网络方式如何选择

进入 `系统设置 → 网络与接口`，在 `手机控制网络方式` 中选择使用方式

| 网络方式 | 适用场景 | 手机与电脑需要同一局域网 | 手机访问地址 | 主要注意事项 |
| --- | --- | --- | --- | --- |
| 本机局域网 | 手机和电脑在同一家庭、宿舍或校园网络 | 是 | `http://局域网IP:端口/...` | 可能受防火墙、访客网络或 AP 隔离影响 |
| Cloudflare Tunnel | 手机不在电脑所在局域网，或局域网无法互访 | 否 | 临时的 `https://*.trycloudflare.com/...` | 依赖 Cloudflare 网络，临时地址会变化 |

切换网络方式时，如果这些服务正在运行，软件会尝试更新现有服务的访问地址。请以电脑端当前显示的二维码和地址为准，不要继续使用切换前保存的旧地址

## 📱 第一步：启动手机控制

完成普通登录后，进入侧边栏的 `手机控制` 页面

页面会显示：

- 服务状态
- 手机访问二维码
- 手机访问地址
- 当前连接设备数
- 固定端口
- 访问令牌
- `启用手机控制` / `停用手机控制` 按钮
- `服务详情` 和 `自动开启`

点击 `启用手机控制`

启动成功后：

1. 服务状态会变为运行中，并显示实际使用的网络方式
2. 页面会生成新的手机访问二维码
3. 二维码下方会显示完整访问地址
4. 使用手机微信或浏览器扫描二维码即可打开控制页面


## 🏠 使用本机局域网模式

### 配置步骤

1. 进入 `系统设置 → 网络与接口`
2. 将 `手机控制网络方式` 选择为 `本机局域网`
3. 确认手机和电脑连接在同一个局域网
4. 回到 `手机控制` 页面
5. 点击 `启用手机控制`
6. 如果 Windows 弹出防火墙提示，请允许 IGoLibrary-Ex 在当前可信网络上通信
7. 用手机扫描二维码打开控制页面

### 局域网模式无法访问的常见原因

- 手机使用移动数据，而电脑连接 Wi-Fi 或网线
- 手机和电脑连接了不同的路由器或不同 VLAN
- 当前 Wi-Fi 是访客网络，开启了客户端隔离或 AP 隔离
- Windows 防火墙或第三方安全软件阻止端口监听
- VPN、虚拟网卡或网络优先级导致软件选到了无法从手机访问的地址
- 学校或单位网络禁止设备之间直接通信

## ☁️ 使用 Cloudflare Tunnel 模式

Cloudflare Tunnel 模式会启动应用完整包中附带、或由应用按需下载到当前用户目录的 `cloudflared`，为本机手机控制服务创建一个临时 `trycloudflare.com` HTTPS 地址。该方式不要求手机和电脑处于同一局域网，也不要求用户准备 Cloudflare 账号。

发布页同时提供两种压缩包：无后缀文件名是包含 cloudflared 的默认完整包，文件名带 `-without-cloudflared` 的是额外轻量包。完整包可以直接使用 Tunnel；轻量包第一次选择 Tunnel 时会询问是否从 Cloudflare 官方 GitHub Release 下载项目固定版本，支持 Windows x64、macOS Intel 和 Apple Silicon。组件安装在当前用户的应用数据目录，不需要管理员权限。

按需安装位置为：

- Windows：`%LOCALAPPDATA%\IGoLibrary-Ex\tools\cloudflared\{version}\win-x64`
- macOS：`~/Library/Application Support/IGoLibrary-Ex/tools/cloudflared/{version}/{rid}`，其中 `{rid}` 为 `osx-x64` 或 `osx-arm64`

该目录只保留当前固定版本的可执行文件、`LICENSE.txt` 和 `THIRD-PARTY-NOTICES.txt`；应用不会修改系统 `PATH`。

确认弹窗会显示当前平台的实际安装目录。开始下载后会显示连接、下载、校验、解压和安装进度；下载阶段可以随时暂停、继续或取消。自动续传重试耗尽时会保留当前进度并等待用户点击“继续下载”。主动取消会保留本次应用运行期间的下载片段，再次确认时尽力断点续传；退出应用后未完成片段会被清理。下载成功后应用会自动继续原来的 Tunnel 切换；完整性校验失败或解压安装失败时会立即清理临时下载文件，详情可查看应用日志。

应用每次启动都会重新验证已持久化 Tunnel 模式依赖的 cloudflared。用户手动删除组件、文件损坏或安装不完整时，本次启动会自动切换并持久化为本机局域网，不会在启动过程中弹出下载窗口；需要继续使用 Tunnel 时，请回到 `系统设置 → 网络与接口` 重新选择并按提示下载。

### 配置步骤

1. 进入 `系统设置 → 网络与接口`
2. 将 `手机控制网络方式` 选择为 `Cloudflare Tunnel`
3. 如果当前安装没有有效的 cloudflared，按弹窗提示选择是否下载；暂不下载或取消时会继续保持原网络方式
4. 第一次使用时先保留 `Cloudflare Tunnel 代理方式` 为 `自动检测（推荐）`
5. 回到 `手机控制` 页面
6. 点击 `启用手机控制`
7. 等待软件创建临时公网地址并完成健康检查
8. 启动成功后，用手机扫描新的公网二维码

成功时地址类似：

```text
https://随机名称.trycloudflare.com/?token=访问令牌
```

### 临时地址的特点

- 每次重新创建 Tunnel 时，域名会变化
- 停止手机控制或退出软件后，地址会失效
- 修改代理、Clash/Mihomo 兼容设置或重新启动服务后，应重新扫描电脑端二维码
- Quick Tunnel 的可用性由 Cloudflare 提供，不适合作为长期固定域名或永久在线服务

> [!CAUTION]
> 不要把完整公网地址发送到群聊、论坛、Issue 或公开截图中。完整地址包含访问令牌，得到地址的人可能查看状态并执行手机控制页面提供的操作

## 🌐 Cloudflare Tunnel 代理方式

只有选择 `Cloudflare Tunnel` 后，相关代理设置才会显示

| 代理方式 | 行为 | 建议场景 |
| --- | --- | --- |
| 自动检测 | 尝试读取系统 HTTP 代理；没有可用代理时直接连接 | 不确定如何选择时使用 |
| 使用系统代理 | 强制使用系统检测到的 HTTP 代理；未检测到时启动失败 | 已确认系统代理配置正确 |
| 手动 HTTP 代理 | 使用填写的本机 HTTP/Mixed 代理地址 | Clash/Mihomo 等软件未写入系统代理 |
| 不使用显式代理 | 不向 `cloudflared` 传递 HTTP 代理 | 网络能够直连，或流量已经由 TUN 接管 |

手动代理地址示例：

```text
http://127.0.0.1:7897
```

手动地址必须是 HTTP 代理地址，不能包含账号、密码、路径、查询参数或片段。修改后点击 `应用代理设置`

如果手机控制或快传服务正在使用 Tunnel，应用代理设置时软件会先创建替代 Tunnel；成功后再切换并关闭旧 Tunnel。如果新 Tunnel 创建失败，会保留原来的 Tunnel 和代理设置

## 🔀 Clash/Mihomo 兼容模式

部分 Clash/Mihomo 配置会把 `cloudflared` 或 Cloudflare 域名错误地分流，导致 TLS 连接中断、`EOF`、无法申请 Quick Tunnel 等问题。此时可以尝试兼容模式

兼容模式会通过 Mihomo 本机控制接口临时加载 Cloudflare Tunnel 专用规则，不会改写订阅文件。最后一个 Tunnel 关闭后，软件会尝试恢复原配置

### 两个输入项分别填写什么

| 输入项 | 应填写的内容 |
| --- | --- |
| 活动配置文件 | Clash/Mihomo 当前实际加载的最终运行配置，必须是绝对 `.yaml` 或 `.yml` 路径。建议先留空使用自动发现，自动发现失败时再手动填写 |
| Cloudflare 路由策略 | 上述运行配置中已经存在的代理策略组名称，例如 `境外代理`。名称必须完全一致，不能包含逗号或 `#`；不要填写 `http://127.0.0.1:7897` 之类的代理地址 |

> [!IMPORTANT]
> 如果代理方式为 `自动检测`、`使用系统代理` 或 `手动 HTTP 代理`，并且软件实际检测到了显式代理，`Cloudflare 路由策略` 就不能填写 `DIRECT`。这会让系统代理和兼容规则互相冲突，软件将直接阻止公网快传或公网手机控制启动。只有选择 `不使用显式代理`，并确认网络可以直连或已经由 TUN 接管时，才考虑使用 `DIRECT`

### 具体示例

假设用户订阅了一个名为 `XX云` 的机场服务，Mihomo 正在运行并已开启系统代理，当前实际加载的最终运行配置是：

```text
D:\Mihomo\configs\XX云-runtime.yaml
```

配置中有多个机场节点，并把它们放进了一个名为 `境外代理` 的策略组：

```yaml
external-controller: 127.0.0.1:9090

proxy-groups:
  - name: 境外代理
    type: select
    proxies:
      - XX云-自动选择
      - XX云-香港01
      - XX云-日本01

rules:
  - MATCH,境外代理
```

这里的 `XX云-香港01`、`XX云-日本01` 是具体机场节点，`境外代理` 才是管理这些节点的策略组。因此 `Cloudflare 路由策略` 应填写 `境外代理`，不要填写某个具体节点名称

按下面步骤填写：

1. 确认 Clash/Mihomo 客户端正在运行并已开启系统代理
2. 在 `系统设置 → 网络与接口` 选择 `Cloudflare Tunnel`
3. 将代理方式保留为 `自动检测（推荐）`
4. 打开 `Clash/Mihomo 兼容模式`
5. 第一次尝试时将 `活动配置文件` 留空，让软件自动发现常见客户端
6. 如果提示无法自动发现，在 `活动配置文件` 中填写当前实际加载配置的绝对路径。本例填写：

   ```text
   D:\Mihomo\configs\XX云-runtime.yaml
   ```

   不要为了照抄示例而新建或重命名配置文件。如果客户端实际加载的是 `C:\Users\Alice\AppData\Roaming\io.github.clash-verge-rev.clash-verge-rev\clash-verge.yaml`，就应该填写那个真实路径

7. 在 `Cloudflare 路由策略` 中填写：

   ```text
   境外代理
   ```

8. 点击 `应用兼容设置`，然后重新启动公网快传或公网手机控制

填写完成后，两个输入项应类似：

```text
活动配置文件：D:\Mihomo\configs\XX云-runtime.yaml
Cloudflare 路由策略：境外代理
```

如果仍然失败，请确认该策略组当前选中的机场节点能够访问 Cloudflare，并检查 Clash/Mihomo 日志中 `trycloudflare.com` 最终使用的是该策略组

如果不知道策略组名称，可以打开最终运行配置，只查看 `proxy-groups` 下每一项的 `name`；选择日常可正常联网的总策略组即可。不要为了查名称直接修改该文件，兼容模式会自行生成并加载临时副本

## 🛟 Tunnel 故障时是否回退局域网

选择 `Cloudflare Tunnel` 后会显示 `Tunnel 故障时回退到本机局域网` 开关

### 开启回退

- Tunnel 启动失败或运行中断时，软件自动改用局域网地址
- 当前网络方式会保存为 `本机局域网`
- 手机控制、Cookie 快传和签到授权快传会显示新的局域网地址
- 手机必须与电脑处于可互访的局域网，回退后的地址才能使用

### 关闭回退

- Tunnel 不可用时不会静默改用局域网地址
- 启动阶段创建 Tunnel 失败时，对应服务会启动失败并提示查看日志
- 已运行的 Tunnel 中断时会保持 Tunnel 模式并报告错误
- 修复网络或代理后，可以重新启动服务或重新应用相关设置

如果你更重视“远程访问失败时绝不暴露局域网地址”，建议关闭回退；如果你希望手机和电脑在同一网络时优先保证可用性，可以开启回退

## 🔔 Cloudflare Tunnel 运行中断通知

在“自动通知 → 通知事件开关”中可以配置 `Cloudflare Tunnel 运行中断提醒`。此事件默认开启，并复用已启用的 Toast 弹窗、提示音、SMTP 邮件、Telegram、Bark、WxPusher 和 Server酱渠道。

只有同时满足以下条件时才会发送：

- 手机控制已经启动，并且实际使用 Cloudflare Tunnel
- Tunnel 已经取得公网地址并通过启动健康检查
- 随后运行中的 `cloudflared` 意外退出、连续健康检查失败或监控异常，导致手机控制公网地址不可用

Tunnel 在手机控制启动阶段便不可用、用户主动停止手机控制、切换网络方式、应用代理设置、退出软件，或只有 Cookie/签到授权快传运行时，都不会发送这项通知。启动失败仍按原有流程显示本地错误或回退提示并记录日志。

通知会说明本次故障的处理结果：已回退本机局域网、保持 Tunnel 模式，或已经回退但网络方式设置保存失败。通知正文不会包含公网地址、访问令牌、代理凭据或底层异常；如需排查技术原因，请查看应用日志。

关闭自动回退且手机控制与授权快传同时运行时，软件会在 15 秒内合并同一轮 Tunnel 故障。若手机控制也在该时间内中断，只发送手机控制运行中断事件，不再叠加授权快传的通用 Toast；若手机控制保持正常，授权快传的原有本地警告会在合并窗口结束后显示。

当“手机控制网络方式”为 `本机局域网` 时，这个事件开关会自动隐藏；重新选择 `Cloudflare Tunnel` 后会恢复显示，原先保存的开启或关闭状态不会被重置。运行故障自动回退到局域网后，开关也会立即隐藏。

## 📊 手机页面可以做什么

打开手机控制页面后，可以查看：

- Cookie 是否有效、保存时间、到期时间和剩余时间
- 当前预约的场馆、座位、到期时间和剩余时间
- 抢座、全域捡漏、明日预约和占座任务的运行状态与日志摘要
- 当前是否存在运行中的任务

可以执行：

- 使用最近一次电脑端成功接受的配置启动抢座或全域捡漏
- 使用电脑端占座页面的当前参数启动占座
- 刷新普通登录 Cookie
- 取消当前运行的任务
- 取消当前预约

启动任务、取消任务、取消预约等操作会要求确认。操作完成后，页面会重新刷新状态

## ▶️ 在手机上启动任务

> [!NOTE]
> 抢座和全域捡漏分别最多保留最近 5 个电脑端配置

### 启动抢座

1. 先在电脑端选择场馆、座位、轮询模式和预约策略，并成功提交一次抢座启动请求
2. 手机页面通过选择框提供最近使用的配置；选项只显示场馆和座位，不显示记录时间
3. 在选择框中选择记录，并在下方摘要中核对场馆、座位、轮询模式和预约策略
4. 点击 `使用所选记录启动` 并确认

手机重放会立即启动，不会重放电脑端原来的定时启动时间。若电脑端从未成功接受过抢座启动请求，手机页面只显示提示，不提供启动按钮

### 启动全域捡漏

1. 先在电脑端确认场馆优先级和扫描间隔，并成功提交一次全域捡漏启动请求
2. 手机页面通过选择框提供最近使用的配置；选项不显示记录时间，场馆顺序就是重放时的扫描优先级
3. 在选择框中选择记录，并在下方摘要中核对场馆顺序和扫描间隔
4. 点击 `使用所选记录启动` 并确认

### 启动占座

占座不使用历史记录。启动时，电脑端会读取占座页面当前填写的重约延迟和检测间隔模式，并要求当前账号已有可续占预约。核对电脑端参数后，在手机页面点击 `开启占座` 即可


## 🍪 在手机上刷新 Cookie

手机控制页面的 `Cookie 状态` 卡片中包含 `刷新 Cookie` 区域

1. 展开 `刷新 Cookie`
2. 在微信内长按识别页面显示的授权二维码；无法长按时可以截图后用微信扫一扫识别
3. 进入“我去图书馆”授权页面
4. 点击右上角的 `...`
5. 点击 `复制链接`，复制包含 `code` 的完整授权链接
6. 返回手机控制页面
7. 将链接粘贴到 `刷新 Cookie 授权链接`
8. 点击 `刷新 Cookie`
9. 等待页面提示成功，并核对 Cookie 到期时间

## 🛠️ 常见问题

### 提示“没有找到可用的局域网 IPv4 地址”

请检查电脑是否已经连接 Wi-Fi 或网线，并暂时停用可能干扰地址选择的无效虚拟网卡。也可以改用 Cloudflare Tunnel 模式

### 局域网二维码可以扫描，但页面打不开

1. 确认手机没有切换到移动数据
2. 确认手机和电脑在同一个局域网
3. 检查 Windows 防火墙是否允许本程序
4. 检查路由器是否开启访客隔离或 AP 隔离
5. 尝试使用手机热点连接电脑，排除校园网络限制

### Cloudflare Tunnel 启动失败

先检查：

1. 如果提示“当前安装未包含 cloudflared”，回到 `系统设置 → 网络与接口`，先切换到本机局域网，再重新选择 `Cloudflare Tunnel` 并按提示下载；也可以改用同版本、同架构且文件名不带 `-without-cloudflared` 的默认完整包
2. 电脑是否能够访问互联网
3. 系统时间是否正确
4. 代理软件是否正在运行
5. `自动检测` 是否找到了正确代理
6. 手动 HTTP 代理端口是否填写正确
7. TUN 分流是否阻断 `cloudflared`、`api.trycloudflare.com` 或 `argotunnel.com`
8. 是否需要启用 Clash/Mihomo 兼容模式并选择可用策略组

### 提示已回退到本机局域网

说明 Tunnel 启动或运行失败，并且故障回退开关处于开启状态。手机与电脑在同一局域网时，可以重新扫描局域网二维码继续使用；否则需要修复 Cloudflare 网络后重新选择 Tunnel 模式。只有手机控制先成功通过 Tunnel 运行、之后才发生的中断会进入自动通知事件；启动阶段失败不会发送该事件

### 公网地址过一段时间失效

Quick Tunnel 是临时服务。电脑休眠、网络变化、软件退出、Tunnel 进程中断或服务重启都可能使原地址失效。回到电脑端重新启动手机控制并扫描最新二维码

### 页面提示无权限或地址失效

- 确认使用的是电脑端当前显示的完整地址
- 不要手动删除 URL 中的 `token` 参数
- 如果切换过网络方式或重新创建过 Tunnel，请重新扫码

### 抢座或全域捡漏没有可用记录

记录只在电脑端启动请求被任务协调器接受后静默保存，手机启动不会创建或提升记录。请先回到电脑端完成一次对应任务的启动；若同类记录已经超过 5 种，最旧记录会被自动淘汰

### 修改端口、令牌或代理后手机断开

这些设置会导致服务或 Tunnel 重新启动。等待电脑端显示新的运行状态后，重新扫描二维码即可
