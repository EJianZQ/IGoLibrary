# 数据备份、恢复与 WebDAV 同步指南

## 备份密码

- 首次导出或上传时需要设置 12～256 位密码并再次确认。
- 密码原样使用，支持 Unicode，不会自动裁剪，也不会写入日志或备份文件。
- 密码无法找回。没有正确密码就无法解密备份。
- 更改密码只影响以后创建的备份，不会修改已有本地备份。
- WebDAV 已配置时，更改密码会要求立即用新密码重新加密上传；取消则不会改密。若网络中断导致无法确认远端是否已接收新备份，本机会继续使用新密码，并在安全凭据存储中暂存旧密码；此时不能再次改密，下一次手动上传成功后才会清除旧密码恢复副本。

Windows 使用 Credential Manager，macOS 使用 Keychain 保存备份密码和 WebDAV 密码。其他平台若没有持久安全凭据，只支持当前运行期间的手动操作，自动上传不可用。

## 本地导出与导入

选择“导出全部数据”，指定 `.igobackup` 文件位置即可

选择“从备份文件导入”后：

1. 输入该文件的备份密码。
2. 应用完成格式、认证标签、清单、SHA-256、数据库标识、结构版本和 `PRAGMA quick_check` 校验。
3. 对比窗口显示创建时间、版本、来源、大小，并可按分类展开查看新增、删除、变更、未变数量及安全字段摘要；协议正文只显示长度与哈希。Cookie、Token、通知密钥和密码只显示配置状态，不显示内容。
4. 勾选“了解当前本地数据将被覆盖”。
5. 若有抢座、全域捡漏、占座或明日预约任务，再次确认后应用会有序停止这些任务。
6. 应用重启并执行可回滚恢复；当前数据目录和日志目录保持不变。

本地文件导入后，自动上传会暂停，必须手动确认是否用导入后的数据覆盖远端。

## WebDAV 配置

填写 WebDAV Endpoint、同步目录、用户名和密码。应用不允许自定义远端文件名，固定使用：

```text
IGoLibrary-Ex.igobackup
```

默认同步目录是 `IGoLibrary-Ex`，因此默认完整远端路径为 `IGoLibrary-Ex/IGoLibrary-Ex.igobackup`。同步目录可以填写多级路径，留空表示直接使用 Endpoint 根目录；目录不能包含 `.`、`..` 或路径穿越。

用户名和密码必须同时填写，或同时留空使用匿名访问。Endpoint 必须是绝对 HTTP/HTTPS 地址，不能包含 URI 用户信息、查询参数或片段；应用会自动补齐结尾的 `/`。

TLS Verify 默认为 `Verify`，使用系统证书校验。仅在自签名证书等明确场景下才可选择 `Skip`；保存时必须确认风险，设置页会持续显示警告。`Skip` 会同时跳过证书链、有效期和主机名校验，可能导致 WebDAV 登录凭据被中间人截获。该选项只作用于 WebDAV 客户端，不影响应用的其他网络请求。

优先使用 HTTPS。使用 HTTP 时 TLS Verify 不适用，应用会再次显示明文凭据风险，并在设置页持续显示警告。

“测试连接”会执行 `PROPFIND Depth: 0`、按需逐级 `MKCOL`，再创建并删除随机探测文件，以验证读取、建目录、写入和删除权限。

## 手动上传、下载覆盖与冲突

手动上传会先刷新尚未落盘的设置，再生成加密快照。远端只保留一个固定文件：

- 首次创建使用 `If-None-Match: *`。
- 已有同步基线时只把匹配的强 ETag 视为可直接使用的验证器；基线或当前响应缺少强 ETag 时，会重新校验远端 SHA-256。
- 远端版本未知或发生变化时不会直接覆盖。应用会显示冲突，只有再次确认后才使用最新验证值执行条件上传。
- 当前响应没有强 ETag 时，即使内容哈希仍与基线一致，自动上传也会暂停并要求手动确认；服务端连 Last-Modified 也不提供时会拒绝覆盖，因为无法执行最基本的条件请求。

“下载并覆盖”与本地导入复用同一套解密、校验、对比、任务确认和恢复事务。云恢复成功后会把本次下载的端点指纹和远端验证值记录为新基线，避免重启后立即反向上传。

## 自动上传

自动上传默认关闭。启用后，持久数据成功写入会进入 dirty 状态：

- 最后一次变更静默 30 秒后上传；连续变更最多延迟 5 分钟。
- 上传期间产生的新变更会保留并再次排队。
- 正常退出前，应用先刷新设置，再提供最多 20 秒的补传窗口；超时保留 dirty 状态，下次启动继续。
- 启动时会重算规范化语义指纹，补偿崩溃窗口或迁移造成的漏通知。
- 远端 ETag/哈希与基线不一致时自动上传立即暂停，绝不静默覆盖。
- 首次启用时若远端已有文件且本地没有基线，会暂停并要求下载覆盖或手动确认覆盖。

## 常见错误

- `401/403`：检查用户名、密码和目标目录权限。
- `404`：检查 Endpoint；目标同步目录可由应用逐级创建。
- `408/429/5xx`：可恢复请求最多重试 3 次，并尊重 `Retry-After`。
- `412`：确认后远端又发生变化，本次上传已取消，请重新检查。
- 配额或磁盘不足：释放服务端或本地空间后重试。
- 证书错误：优先修复服务端证书链或使用受信任的 HTTPS 地址；只有在明确了解风险时才使用 TLS Verify `Skip`。
- 密码错误或文件损坏：确认备份密码；若密码正确，则文件可能不完整或已被篡改。
