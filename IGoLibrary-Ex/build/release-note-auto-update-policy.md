# Release Note 自动更新兼容性标记

正式发布新版本时，可以在 GitHub Release Note 的第一条非空行声明支持自动更新的最低客户端版本：

```markdown
<!-- IGoLibrary-Ex-MinAutoUpdateVersion: 1.0.5 -->

### 🚀 新功能

- 更新内容
```

该 HTML 注释不会作为更新说明展示给用户，应用也会在交给 Markdown 组件前移除这条控制标记。

## 格式约束

- 标记必须是 Release Note 的第一条非空独立行。
- 键名必须精确写为 `IGoLibrary-Ex-MinAutoUpdateVersion`，区分大小写。
- 注释外围、键名与冒号之间、冒号与版本之间允许使用空格或 Tab。
- 版本必须是规范的 `N.N.N`，不能带 `v`、前导零或预发布后缀。
- 一个 Release Note 只能出现一次该键；重复相同值也视为无效。
- 最低版本可以等于目标 Release 版本，但不能高于目标版本。

## 客户端行为

- 没有标记：所有包含本功能的客户端均可按原流程自动更新。
- 当前版本大于或等于最低版本：允许自动更新。
- 当前版本低于最低版本：显示更新说明和不兼容警告，只允许用户前往当前 GitHub Release 手动下载。
- 标记无效、重复、位置错误或最低版本高于目标版本：安全失败，只允许手动下载。

例如，目标版本为 `1.1.0` 且标记最低版本为 `1.0.5` 时，`1.0.4` 不能自动更新，`1.0.5` 和 `1.0.6` 可以自动更新。

## 发布检查清单

1. 仅在确实存在自动更新兼容性下限时添加标记；无限制时不要添加空标记或占位值。
2. 确认标记是第一条非空行，且只出现一次。
3. 确认最低版本不高于目标 Release 标签版本。
4. 在 GitHub Release 编辑页预览正文，确认正常的 Markdown 更新说明未受影响。
5. 保持 Windows 自动更新包的现有名称、摘要和上传状态要求不变。

## 向前生效限制

该策略只对已经包含标记解析功能的客户端生效。更早发布的客户端无法通过 Release Note 获得新解析能力，可能忽略标记；
